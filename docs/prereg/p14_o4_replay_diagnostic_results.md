## 0. 이 문서가 부여하지 않는 것

**아래 수치는 전부 진단 도수다.** 게이트도, 과학적 verdict 도 부여하지
않는다. O4 는 여전히 **무판정(`verdict = null`)** 이고 어느 게이트도
통과하지 않았다 — 이 census 는 그 상태를 바꾸지 않으며 G3 재설계의 입력만
제공한다.

**독립 확인도 아니다.** 개발 중 dirty 작업트리에서 부분 replay 로 최소
cluster 604 까지 이미 관측했으므로(프로토콜 §0), 이 실행은 같은 고정
stress 집합의 **나머지 도수를 세는 census** 다.

**이 결과에 맞춰 아무 규칙도 바꾸지 않았다.** η = 10⁻¹², `MAX_NUDGES` =
64, availability 규칙은 census 이전에 정해진 그대로다. 시드 원장도
그대로다 — replay 는 소비가 아니므로 `40,000,301` 은 미할당,
`refs/o4/reservation` 은 `c4da162` 로 보존.

## 3. `err` 는 `tol` 로 상계되지 않는다 — 실측 5자릿수

`tol = 10⁻⁸`.

| 분위 | `err₁` | `err₂` |
|---|---|---|
| 0.001 | 1.000e-08 | 1.000e-08 |
| 0.5 | 1.085e-08 | 1.151e-08 |
| 0.9 | 1.582e-08 | 2.208e-08 |
| 0.99 | 1.760e-07 | 3.430e-07 |
| 0.999 | 6.250e-06 | 8.973e-06 |
| max | 1.199e-03 | **1.156e-03** |

중앙값은 사실상 `tol` 이지만 꼬리가 두껍다 — `err₂` 최댓값은 `tol` 의
**약 10⁵ 배**다. 고정 offset `10⁻⁶` 을 `tol` 대비 두 자릿수 여유로 잡은
것이 `err` 대비 여유를 전혀 보장하지 않는다는 실패의 형태가 수치로
확인된다. `err₂ ≥ 10⁻⁶` 히스토그램 꼬리:

```

[2.15e-06, 4.64e-06)  202     [2.15e-05, 4.64e-05)   28
[4.64e-06, 1.00e-05)  121     [4.64e-05, 1.00e-04)   16
```

## 4. 적격률 — 이 집합에서는 모든 η 에서 100%

| η | 적격 | `t_x < 0` | 적격 ∧ `t_x < 0` |
|---|---:|---:|---:|
| 0 … 10⁻⁶ (전 격자) | 100,000 | 0 | 0 |

`L` 의 최솟값이 2.203e-05 이고 `L − err₁ − err₂` 의 최솟값이 2.201e-05
이므로, 격자 최대치 η = 10⁻⁶ 에서도 `W_robust > 0` 이 전부 성립한다.
η = 10⁻¹² 가 η = 0 과 같은 적격률을 준다는 §4.2 둘째 근거가 실증됐다 —
**실증이지 정당성의 근거가 아니다.** η 의 값은 부동소수점 분리 논거에서
나왔고 이 표는 그 값을 바꾸지 않는다.

하단 probe (iii) 은 **모든 클러스터에서 구성 가능**했다(`t_x < 0` 이 0).
적격 교집합도 0 이므로, 이 집합에서 probe (iii) 의 도달률은 적격 집합 안에서
100% 다.

**이 적격률은 설계 입력일 뿐이다.** 새 캠페인의 통과 증거로 재사용하지
않으며, 새 freeze 전에 §3.5 의 세 규칙 중 하나를 여전히 사전 고정해야 한다.

## 5. 각도 복원 항은 이 집합에서 0 이었다

`|t_min(dpsi) − T(θ)|` 는 두 leg 모두 **min = max = 0**. `dpsi` 의 두
경로도 전부 일치(불일치 0).

이것을 "그 항은 없다"로 읽으면 안 된다. 복원 오차는 `1/θ` 로 커지고
(설계 §4.1), 샘플러가 `cos θ` 를 균등하게 뽑으므로 작은 θ 는 드물다 —
이 10만 개에는 충분히 작은 θ 가 들어오지 않았다는 뜻이다.

**재설계의 결정은 그대로 옳다.** 이 항을 0 으로 만드는 것이 뽑기 운이
아니라 **구성**이어야 한다는 것이 요점이고, 뽑기 운으로 0 인 여유야말로
이 stage 가 계속 발견하고 있는 결함군 그 자체다.

## 6. 무엇이 남았는가

이 census 는 설계 문서 §6 의 사후 동결 항목에 입력을 준다:

- G3b 의 cluster 수와 CP 상계 — 적격률 100% 라는 입력
- §3.5 세 규칙 중 무엇을, 어떤 임계로
- G3a 의 검사점 수와 추출 방식
- 총 비용과 상한

**η 와 `MAX_NUDGES` 는 여기 없다.** 둘 다 census 이전에 반올림 논거만으로
정해졌고 이 결과가 바꾸지 않는다.

다음 순서는 사전등록 재개방(§6 동결) → 새 freeze·새 G1/G2 시드로 O4 전면
재실행이며, 실행 승인은 언제나 동결 승인과 별도다.
